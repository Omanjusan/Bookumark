# DB-15「Firefox実機・性能確認」実装計画

更新日: 2026-07-31

## 現在地

- DB-14「廃止・破損復旧」はDB-14Kの是正と再監査を含めて完了済み。
- DB-15の要求分析、懸念事項のインタビュー、対象範囲、検証方針、機能別フェーズ分割を確定した。
- DB-15A〜Iの実装、必須問題の是正、Firefox実機確認、性能測定、全体回帰を完了した。
- DB-15J完了監査は、ユーザー承認済みのDB15-E-01を後続へ引き渡す条件でPASSとした。

## 1. 目的

DB-1〜DB-14で実装したドッキング機構を正式対象のFirefox実機で検証し、これまで実機確認へ保留していた表示、操作、フォーカス、性能上の調整値を確定する。

DB-15は新機能を広げるフェーズではない。通常条件と高負荷条件で既存機能の成立を確認し、必須問題が見つかった場合だけ必要最小限の是正を行う。

## 2. 完了条件

- 通常fixtureと高負荷fixtureを同じ手順で再現できる。
- ズーム、狭幅、スクロール時にも主要情報が欠落せず、主要操作へ到達できる。
- ベイ工場、レイアウト編集、端パン、ブックマーク操作のD&DがFirefox実機で成立する。
- 長文通知、ダイアログ、トースト、フォーカスが確定した表示・操作契約を満たす。
- 性能対象操作の初回測定結果、ユーザー確認済みの合格基準、最終測定結果を記録できる。
- 操作不能、データ破損・消失、未処理例外、主要情報欠落、著しい待ち時間、D&D失敗、フォーカス喪失、操作へ到達できない表示が残っていない。
- 全自動テスト、Firefox拡張lint、`git diff --check`が成功する。
- 推奨調整の未対応事項とDB-16以降の候補を明示する。

## 3. 正式対象環境

- Linux版Firefox Flatpak
- `develop`プロファイル
- `npm run experiment`による起動
- デスクトップFirefoxのみ

Windows、macOS、Firefox ESRは正式な合格対象に含めない。

## 4. 対象範囲

### 4.1 高負荷fixture

- ブックマーク: 2,000件
- 1レイアウトに配置するベイ: 20個
- 1ベイ内のチップ: 10個
- 合計チップ: 200個
- 上、左、右、下の4レールをすべて使用
- 通常表示とレイアウト編集の両方で検証

### 4.2 ズームと画面条件

- Firefoxズーム: 80%、100%、125%、150%、200%
- 画面条件: 440px相当の狭幅、1280x720、1920x1080
- 基準条件: 100%、1280x720

全15組み合わせでは表示、情報欠落、主要操作への到達可能性を確認する。詳細なD&Dと性能測定は基準条件と、各機能に対して最も厳しい代表条件へ絞る。

### 4.3 表示・スクロール

- リサイズ後の再配置
- レールの収容判定と間隔
- 縦横レールの片軸スクロール
- 横方向エクスパンションと画面端補正
- ズーム時の小数ピクセル丸め
- 2,000件表示時の縦スクロールと情報量

### 4.4 D&D

- ベイ工場でのチップ追加、ベイ内並べ替え、領域外削除
- レイアウト編集でのベイ配置、同一レール内並べ替え、レール間移動、中央ゴミ箱への未配置化
- 上下レールの縦端パンと左右レールの横端パン
- カスタム配置でのブックマーク並べ替え
- 公式整理での同階層移動と別フォルダ移動
- ズーム100%の通常fixtureと、ズーム200%または高負荷fixtureでの代表確認

マウス操作を正式な合格対象とする。キーボードによるベイ配置・並べ替えは対象外とする。

### 4.5 長文通知とフォーカス

- ダイアログ表示時に主操作へフォーカスする。
- `Tab`と`Shift+Tab`でダイアログ外へフォーカスを漏らさない。
- 処理中の二重操作を防止する。
- ダイアログ終了後は、可能なら起点へ戻し、起点が失われていても操作可能な位置へ戻す。
- トーストは現在の入力フォーカスを奪わない。
- 440px相当、ズーム200%、想定最大の復旧詳細でも、本文と主操作をスクロールして確認できる。
- 長文を画面外へ突き抜けさせず、instance IDや例外詳細を利用者向け表示へ出さない。
- ARIA属性と通知領域のDOM契約を自動テストとFirefox開発者ツールで確認する。

スクリーンリーダー固有ソフトによる実際の読み上げ試験は対象外とする。

## 5. 対象外

- 具体的な追加condition/action型
- 既存のロード失敗・保存失敗などを共通通知へ全面移行する作業
- 通知履歴
- deprecatedチップから代替チップへの設定変換・自動置換
- キーボードによるベイ配置・並べ替え
- スクリーンリーダー固有ソフトによる読み上げ試験
- Windows、macOS、Firefox ESRでの正式検証
- 仮想化、D&D方式変更、状態モデル変更などの大規模な再設計

追加機能4件はDB-16以降の候補として引き渡す。

## 6. 性能評価

### 6.1 測定対象

- 起動から操作可能になるまで
- 表示形式切替
- 検索
- ソート
- レイアウト切替
- レイアウト編集開始
- D&D後の再描画

### 6.2 測定方法

- 100%、1280x720を基準環境とする。
- 高負荷fixtureを使用する。
- ウォームアップ後に各項目を5回測定する。
- 中央値と最大値を記録する。
- 測定区間、開始条件、終了条件を項目ごとに固定する。
- Node上の既存`npm run benchmark:panel`も補助的な回帰値として記録するが、Firefox実機の合否を代替しない。

初回測定前に根拠のない固定時間を置かない。初回測定結果を報告してSTAYし、ユーザー確認後に数値基準を確定する。その後、同じ条件で再測定して最終合否を判定する。

未処理例外、操作不能な停止、データ欠落は測定時間に関係なく不合格とする。

## 7. 問題の分類

| 区分 | 例 | 扱い |
| --- | --- | --- |
| 必須 | 操作不能、データ破損・消失、未処理例外、主要情報の欠落 | DB-15完了前に修正する |
| 必須 | 著しい待ち時間、D&D失敗、フォーカス喪失、表示によって操作へ到達できない | DB-15内で必要最小限の修正を行う |
| 推奨 | 情報欠落を伴わない軽微な余白や見た目の差 | 原則調整し、変更コストが過大なら後続候補へ記録する |
| 推奨 | 仮想化、D&D方式変更、状態モデル変更を要する問題 | DB-15で即実装せず、別フェーズとして再計画する |

必須問題の修正が複数機能へ分かれる場合は、DB-15HをDB-15H-1、DB-15H-2のように分割し、それぞれ独立してGO確認する。

## 8. 要求分析で解消した懸念事項

| 懸念 | 決定 |
| --- | --- |
| DB-14からの追加機能までDB-15へ含めると範囲が膨らむ | DB-15へ含めず、DB-16以降へ分離する |
| 正式対応環境が広がりすぎる | Linux版Firefox Flatpakと`develop`プロファイルに限定する |
| 大量ベイ・チップの基準がない | 2,000ブックマーク、20ベイ、各10チップに固定する |
| ズームと画面幅の検証範囲が不明 | 5倍率と3画面条件を正式範囲にする |
| 性能基準に根拠がない | 初回実測後にユーザー確認を受けて確定する |
| D&Dの対象操作が曖昧 | ベイ工場、レイアウト編集、端パン、ブックマークの4系統を対象にする |
| アクセシビリティ試験が環境依存で拡大する | フォーカス、ARIA、DOM契約までを正式対象にする |
| 発見した問題によってDB-15が際限なく拡大する | 必須修正と大規模再設計を分離する |

## 9. テスト観点

### 9.1 fixture

- 通常fixtureと高負荷fixtureを手順どおり再作成できる。
- 高負荷fixtureの件数、ID、4レールへの配置が毎回同じになる。
- fixture投入前の利用者データを誤って上書きしない。
- 検証後に`develop`プロファイルを既知の状態へ戻せる。

### 9.2 表示・ズーム・スクロール

- 全15条件で主要情報と主要操作が欠落しない。
- 440px相当と200%でも必要なスクロールによって全操作へ到達できる。
- 画面全体に意図しない横スクロールを発生させない。
- 縦横レールは向きに対応する片軸だけをスクロールする。
- リサイズ中の中間状態で再描画を連発せず、最終寸法へ安定する。
- ズーム時にもドロップ位置、プレビュー、挿入インジケータが一致する。

### 9.3 D&D

- ドラッグ開始、プレビュー、挿入位置、drop結果が一致する。
- キャンセルと領域外dropでドラッグ状態を残さない。
- 同一レール内移動と別レール移動で重複配置を作らない。
- 中央ゴミ箱はドラッグ中だけ有効になり、対象ベイだけを未配置化する。
- スクロール可能な方向だけ端パンし、dropまたはキャンセルで停止する。
- カスタム配置と公式整理の書き込み先を混同しない。
- 公式整理失敗時にFirefoxツリーを再取得し、操作可能な表示へ戻る。

### 9.4 通知・フォーカス

- ダイアログ表示、フォーカストラップ、処理中ガード、終了後復帰が成立する。
- トーストはフォーカスを奪わず、ARIA live regionを維持する。
- 長文でも見出し、本文、主操作が欠落しない。
- 利用者向け本文へ内部IDや例外詳細を出さない。

### 9.5 性能・異常時

- 7操作を同じ開始・終了条件で5回測定できる。
- 高負荷条件で操作不能な停止、未処理例外、データ欠落がない。
- 必須問題を再現する自動テストまたは実機手順が、修正前に失敗する。
- 修正後に対象テスト、全体回帰、同じ実機手順が成功する。

## 10. TDD・検証方針

- Firefox固有の見た目や操作感は、事前に確定した手動テストケースで検証する。
- 自動化可能なfixture生成、計測、境界処理はテスト先行とする。
- 必須問題の修正は再現テストをRedとして追加してからGreenへ進む。
- D&D、保存、状態、フォーカスに触れる修正はTDDを必須とする。
- 純粋なCSS定数調整は、確定した実機再現手順の不合格をRed相当の根拠として扱う。
- 各フェーズを`GO確認 → Redまたは実機不合格確認 → Greenまたは検証 → 全体回帰 → progress.md更新 → コミット文案 → STAY`の単位で進める。
