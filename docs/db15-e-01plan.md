# DB15-E-01「レール上限・端パン」独立フェーズ引き渡し

更新日: 2026-07-31

## 0. 文書の位置づけ

本書は、DB-15でユーザー承認のうえPENDINGとしたDB15-E-01を、独立フェーズとして再開するための入口である。

この文書は実装計画の確定版ではない。次チャットでは本書を参照し、**要求分析 → 懸念事項インタビュー → 仕様確定 → テストケース設計 → 機能別実装計画**の順で策定する。要求分析が終わるまで実装へ進まない。

## 1. 現在判明している問題

4方向のレールには向きに対応する`overflow`が設定され、端パンの計算・適用処理も存在する。しかし、レール表示領域の幅または高さに実効的な上限がないため、内容が増えるとレール自体が拡大する。

その結果、次の状態になっている。

- スクロール可能なレール領域が成立せず、端パンを実機で発生させられない。
- 同一レールへ多数のベイを配置すると、中央表示や主要操作が押し出される。
- 200%ズーム・狭幅で20個の配置済み空ベイが残る再現条件では、通常UIが人間的に操作困難になった。
- データ破損、保存失敗、既知の未処理例外は確認されていない。
- ベイ数が少ない通常レイアウトでは、直ちに支障は確認されていない。

## 2. 端パンの目的

端パンは、ベイまたはブックマークをD&Dしている間に、レールからあふれて見えない挿入位置へ到達するための機能である。

上下レールは縦方向だけ、左右レールは横方向だけをスクロールする。レール内の複数ベイは全方向で外側から内側へ増える既存契約を維持する。

## 3. DB-15で保留した理由

レールへ単純な固定値を設定すると、中央表示の最低寸法、画面占有率、ズーム、狭幅、ベイの固有寸法、4方向同時使用の優先関係へ影響する。これらはCSS調整だけで確定できる事項ではなく、プロダクト仕様の判断を必要とする。

DB-15はFirefox実機・性能確認と必須問題の必要最小限の是正に限定していたため、暗黙に大規模なレイアウト仕様を追加せず、独立フェーズへ分離した。

## 4. 確定済み事項

- 端パン機能そのものは削除しない。
- 上下レールのベイは垂直、左右レールのベイは水平に並ぶ。
- 全レールで、保存順の先頭を外側として内側へ増やす。
- レールは向きに対応する片軸だけをスクロールする。
- dropまたはドラッグキャンセル後に端パン状態を残さない。
- DB-15の正式対象環境はLinux版Firefox Flatpak、`develop`プロファイルである。
- DB-15の表示確認条件は80%、100%、125%、150%、200%と、440px相当、1280x720、1920x1080である。
- DB15-E-01以外のDB-15完了条件と全153自動テストは合格済みである。

## 5. 未確定事項

次チャットの要求分析とインタビューで、少なくとも以下を確定する。

1. 上下・左右レールの上限を固定値、画面比率、中央領域の最低寸法のどれで決めるか。
2. 4レールを同時に使う場合の領域配分と、中央表示へ保証する最低寸法。
3. 狭幅・高ズーム時にレールを縮小、折り畳み、スクロールのどれで成立させるか。
4. ベイ固有寸法がレール表示領域より大きい場合の扱い。
5. スクロールバーを常時表示するか、overflow時だけ表示するか。
6. 端パンの発火領域、速度、連続動作、端到達時のフィードバック。
7. マウスD&D以外の入力方式を今回の対象へ含めるか。
8. 既存レイアウト文書や保存形式を変更せずに実現するか。

質問総数は要求分析後に提示する。現時点の初期見積もりは上記8論点を約3回に分け、各回2〜3問である。

次チャットでは、ユーザーから「DB15-E-01の要求分析を開始。`docs/db15-e-01plan.md`を参照」の指示を受けたものとして進行する。

## 7. 要求分析時の対象候補

- レール表示領域の上限と中央領域の最低寸法
- 4方向同時使用時のグリッド配分
- 片軸スクロールとスクロールバー表示
- D&D中の端パン開始・継続・停止
- リサイズ、ズーム、レイアウト切替後の再計算
- 多数ベイおよび単一巨大ベイの境界値
- DB-15高負荷fixtureを用いたFirefox実機確認

## 8. 対象外候補

要求分析で変更されない限り、以下は対象外候補とする。

- ベイ内部のチップ配置方向の再設計
- レイアウト文書のschema変更
- ブックマーク公式整理・カスタム配置D&Dの意味変更
- 仮想化などの大規模性能再設計
- Windows、macOS、Firefox ESRの正式検証
- キーボードによるベイ配置・並べ替え

## 9. 完了条件のたたき台

次チャットで確定するための初期案であり、まだ仕様ではない。

- 多数ベイでも中央表示と主要操作へ到達できる。
- 4レールが定めた上限内に収まり、必要な片軸スクロールが成立する。
- 上下は縦、左右は横にだけスクロールする。
- D&D中に見えない挿入位置まで端パンで到達できる。
- drop、キャンセル、領域外終了後にパンが継続しない。
- 80%〜200%および規定画面条件で、意図しないページ全体の横スクロールを発生させない。
- 保存・再読込後も配置順と表示契約を維持する。
- 既存のDB-15実機項目、全自動テスト、Firefox拡張lint、差分検査が成功する。
