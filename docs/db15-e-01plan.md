# DB15-E-01「レール上限・端パン」独立フェーズ引き渡し

更新日: 2026-07-31

## 0. 文書の位置づけ

本書は、DB-15でユーザー承認のうえPENDINGとしたDB15-E-01を、独立フェーズとして実装・検証するための確定計画である。

2026-07-31に、**要求分析 → 懸念事項インタビュー → 仕様確定 → テストケース設計 → 機能別実装計画**を完了した。以降は本書のフェーズごとにGO確認、Red-Green、回帰、記録、STAYで進める。

## 1. 現在判明している問題

4方向のレールには向きに対応する`overflow`が設定され、端パンの計算・適用処理も存在する。しかし、レール表示領域の幅または高さに実効的な上限がないため、内容が増えるとレール自体が拡大する。

その結果、次の状態になっている。

- スクロール可能なレール領域が成立せず、端パンを実機で発生させられない。
- 同一レールへ多数のベイを配置すると、中央表示や主要操作が押し出される。
- 200%ズーム・狭幅で20個の配置済み空ベイが残る再現条件では、通常UIが人間的に操作困難になった。
- データ破損、保存失敗、既知の未処理例外は確認されていない。
- ベイ数が少ない通常レイアウトでは、直ちに支障は確認されていない。

## 2. 端パンの目的

端パンは、ベイまたはブックマークをD&Dしている間に、レールからあふれて見えない挿入位置へ到達するための機能である。

上下レールは縦方向だけ、左右レールは横方向だけをスクロールする。レール内の複数ベイは全方向で外側から内側へ増える既存契約を維持する。

## 3. DB-15で保留した理由

レールへ単純な固定値を設定すると、中央表示の最低寸法、画面占有率、ズーム、狭幅、ベイの固有寸法、4方向同時使用の優先関係へ影響する。これらはCSS調整だけで確定できる事項ではなく、プロダクト仕様の判断を必要とする。

DB-15はFirefox実機・性能確認と必須問題の必要最小限の是正に限定していたため、暗黙に大規模なレイアウト仕様を追加せず、独立フェーズへ分離した。

## 4. 確定済み事項

- 端パン機能そのものは削除しない。
- 上下レールのベイは垂直、左右レールのベイは水平に並ぶ。
- 全レールで、保存順の先頭を外側として内側へ増やす。
- レールは向きに対応する片軸だけをスクロールする。
- dropまたはドラッグキャンセル後に端パン状態を残さない。
- DB-15の正式対象環境はLinux版Firefox Flatpak、`develop`プロファイルである。
- DB-15の表示確認条件は80%、100%、125%、150%、200%と、440px相当、1280x720、1920x1080である。
- DB15-E-01以外のDB-15完了条件と全153自動テストは合格済みである。

## 5. 確定仕様

### 5.1 全体利用幅と中央領域

- `.frame`の`max-width: 640px`を撤廃し、全体利用幅をウィンドウ幅の96%とする。
- ウィンドウのリサイズへ追従し、再読込なしで再配置する。
- 96%は将来差し替えられる単一定義へ分離する。ただし設定画面、値の保存、入力検証、初期化は完全に対象外とし、設計余地だけを残す。
- 中央のブックマーク領域は原則270px以上を確保する。
- ウィンドウ自体が270pxより狭い場合は、利用可能な幅を中央へ優先して渡し、ページ全体へ意図しない横スクロールを発生させない。

### 5.2 レール上限と縮退

- 上・下レールは、それぞれウィンドウ高さの25%を上限とする。
- 左・右レールは、それぞれ全体利用幅の20%を上限とする。
- 中央270pxと左右20%を同時に満たせない場合は、中央を優先して左右レールを20%未満へ縮める。
- 狭幅・高ズームでもレールを自動的に非表示または折り畳みにしない。
- 内容が収まる場合はスクロールバーを表示せず、収まらない場合だけ表示する。
- 上下レールは縦、左右レールは横の片軸だけをスクロールする。
- ベイ間隔は既存どおり8px、4px、2pxの順で縮め、その後スクロールへ移る。

### 5.3 単一巨大ベイ

- 上下レールの横長ベイは、外枠をレール幅以内に収め、長い内容だけをベイ内部で横スクロールする。
- 左右レールの縦長ベイは、外枠を表示可能な高さ以内に収め、長い内容だけをベイ内部で縦スクロールする。
- 内容を縮小、折り返し、切り捨てない。ベイ名などの識別部分は可能な限り表示したままにする。
- レールは複数ベイの並び軸、ベイ内部は内容が長くなる軸を担当し、入れ子のスクロールを混同しない。

### 5.4 ベイD&D端パン

- マウスによるベイD&Dだけをレール端パンの対象とする。ブックマークD&Dはレールへ配置する既存契約がないため対象に含めない。
- ポインターがレール端へ近づくと開始し、端へ近いほど速くする。
- ポインターを動かさず端に置いたままでも、見えない挿入位置へ到達するまで連続動作する。
- 端の発火範囲から離れたとき、drop、キャンセル、領域外終了時は直ちに停止する。
- レール終端を越えず、端到達後に画面の揺れやページ全体のスクロールを起こさない。
- キーボードとタッチによる配置・並べ替えは対象外とする。

### 5.5 再配置、切替、保存

- リサイズ時は現在のレールスクロール位置を可能な限り維持し、成立しない場合だけ最も近い有効位置へ補正する。
- レイアウト切替時は新しい各レールを外側の先頭から表示し、切替前レイアウトのスクロール位置を引き継がない。
- 保存形式、ベイ配置、保存順を変更しない。
- 全レールで保存順の先頭を外側として内側へ増やす既存契約を維持する。

## 6. 対象範囲

- 全体利用幅96%とリサイズ追従
- レール上限、中央領域優先、4方向同時使用時のグリッド配分
- レールの片軸スクロールと必要時だけのスクロールバー
- 横長・縦長ベイ内部の別軸スクロール
- ベイD&D中の端パン開始、連続動作、停止
- リサイズとレイアウト切替後のスクロール位置
- 20ベイおよび単一巨大ベイの境界値
- DB-15高負荷fixtureを用いたFirefox実機確認

## 7. 対象外

- 利用幅を変更する設定画面、設定保存、入力検証、初期化
- ベイ内部のチップ配置方向の再設計
- レイアウト文書のschema変更
- ブックマークD&Dへのレール端パン追加
- ブックマーク公式整理・カスタム配置D&Dの意味変更
- 仮想化、D&D基盤、状態モデルの大規模再設計
- Windows、macOS、Firefox ESRの正式検証
- キーボードまたはタッチによるベイ配置・並べ替え

## 9. TDD・実機検証方針

- 寸法計算、速度計算、連続駆動、停止処理、位置補正、保存順は自動テストをRedとして先行する。
- CSS定数とFirefox固有表示は、確定した再現手順の不合格およびCSS契約テストをRedとする。
- ズーム、スクロールバー、ポインター静止中の連続端パン、入れ子スクロールの操作感はFirefox実機で確認する。
- 各実装フェーズは`GO確認 → Red → Green → 対象テスト → 全体回帰 → progress.md更新 → コミット文案 → STAY`で進める。
