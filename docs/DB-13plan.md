## 確定仕様

### チップ種別

基本6チップ（検索、訪問状態、フォルダー履歴、ソート、表示形式、移動モード）はすべて `control` とする。condition/actionの統合契約には、具体型が追加されるまで注入可能なテスト用定義を使う。

### 初期化と適用順

1. デフォルト共有状態を生成する。
2. activeレイアウトの配置順でconditionチップを評価する。
3. condition評価後の最終共有状態をcontrolが読む。
4. いずれかのcontrol更新時は、同じ共有状態を読む全controlへ同期する。
5. actionは初期化時に実行せず、ユーザーの明示操作時だけ実行する。
6. レイアウト選択controlは `activeLayoutId` を表示用に読むが、初期化中にレイアウトを自動切り替えしない。

配置順は上、左、右、下のレール順、各レール内のベイ順、各ベイ内のチップ順とする。未配置ベイは対象外。同じキーは後の成功結果を採用し、異なるキーは累積する。

### Docking共有状態

標準キーは `query`、`filters`、`sort`、`viewType`、`movementMode`、`activeLayoutId` とする。標準キー以外は将来のチップのため保持し、パネルは標準キーだけを解釈・検証する。不正な標準値を返したconditionは全体を原子的に失敗させる。`activeLayoutId` は初期化中にconditionから変更できない。

### conditionの原子的評価

- 各conditionの直前状態と設定をcloneし、そのcloneだけを定義へ渡す。
- 成功し、オブジェクトであり、標準キーが妥当な結果だけを次状態として採用する。
- 例外、非オブジェクト結果、clone不能値、不正な標準キーはそのチップの失敗とする。
- 失敗時は適用前状態を完全に維持し、後続チップを続行する。
- 入力レイアウト文書、チップ設定、適用前状態を変更しない。
- 失敗は `{ instanceId, chipType, reason }` の構造で返し、consumerが `console.warn` を記録する。
- ユーザー通知は統合通知の別課題、unknown/deprecated定義の最終復旧はDB-14とする。

### controlとaction

- controlはcondition評価後の共有状態から値を読む。
- control操作は共有状態を更新し、同じ状態を参照する全controlとメイン表示へ同期する。
- 同種controlが複数配置されていても表示値を同期する。
- actionは共有状態を参照できるが、初期化・再構築だけでは発火しない。
- actionの失敗は他のruntimeとメイン表示を停止させない。

### 保存後の再評価と再構築

- 保存失敗時はドラフト、履歴、未保存状態、runtimeを変更しない。
- 保存成功時は履歴を空にし、保存基準点を更新する。
- 保存成功直後に検索、フィルター、ソート、表示形式、移動モード、一時的な履歴状態をリセットする。
- 保存済みメインレイアウト文書をstorageから再読込し、activeレイアウトを再評価する。
- 編集モードは継続し、通常runtimeへはまだ再接続しない。非activeレイアウトの編集プレビューは維持する。
- 編集終了時に保存済み状態から通常runtimeを再接続する。
- 保存は成功したがstorage再読込だけが失敗した場合、保存候補の防御的コピーを使って再評価する。
- 再読込失敗は構造化警告と `console.warn` へ記録するが、保存成功を取り消さず、保存再試行も表示しない。
- 次回起動時は通常どおりstorageから読み込む。

## テストケース設計

### 正常系

- 4レール、ベイ、チップの規定順で適用される。
- 同じ標準キーは後方優先、異なるキーは累積する。
- condition評価後の最終値を基本6 controlが読む。
- control更新が同種control、関連control、メイン表示へ同期する。
- actionは明示操作時だけ一度実行される。

### 異常系

- unknown定義、kind不一致、`apply` 例外を記録し、後続を継続する。
- 非オブジェクト、clone不能、不正な標準キーを原子的に破棄する。
- 失敗が先頭、中間、末尾のいずれでも、成功済み状態と後続結果が保たれる。
- action失敗が他のruntimeとメイン表示を停止しない。

### 境界値と整合性

- 空レイアウト、conditionなし、未配置ベイでデフォルト状態になる。
- 同種controlが複数あっても同期する。
- 入力文書、設定、適用前状態を変更しない。
- `activeLayoutId` の自動変更を拒否する。
- 未知の共有状態キーを保持し、パネルは解釈しない。

### 保存・再構築

- 保存成功時だけ状態リセット、再読込、再評価を各1回行う。
- 保存失敗時は状態、履歴、runtimeを変えない。
- 保存成功後の再読込失敗時は保存候補cloneで再評価し、警告を返す。
- 編集継続中は通常runtimeを再接続せず、編集終了時に再接続する。
