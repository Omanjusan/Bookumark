# AMO unlisted版の提出・導入手順

Bookumarkの公開前テスト版を、AMOで一般公開せずに署名して手動配布する手順。
AMO APIキーやCLI認証は使用しない。AMO開発者サイト上の操作だけで提出する。

## 1. ローカル成果物の生成

リポジトリルートで次を実行する。

```sh
npm test
npm run lint:ext
npm run build:amo
```

`amo-artifacts/`へ次の2ファイルが生成される。

- `bookumark-0.1.1.zip`: AMOへアドオン本体としてアップロードするproduction版
- `bookumark-0.1.1-source.zip`: ソース提出を求められた画面でアップロードする審査用ソース

ソースZIPをアドオン本体の欄へアップロードしない。新しい提出を作るたびに、manifest、
package、lockfileのバージョンを同じ未使用バージョンへ上げてから再生成する。

## 2. AMOへの手動提出

1. AMO開発者サイトへブラウザーでログインし、新しいアドオンまたは新しいバージョンの提出を開始する。
2. 配布方法は自己配布用の`unlisted`（サイト上で一般公開しない）を選ぶ。
3. `bookumark-0.1.1.zip`をアドオン本体としてアップロードする。
4. 生成済みコードのソース提出を求められた場合は、`bookumark-0.1.1-source.zip`を指定する。
5. ビルド方法には、ソースZIP直下の`AMO_BUILD.md`を案内する。
6. 検証結果を確認して提出する。署名完了まで待ち、AMOから署名済みXPIをダウンロードする。

AMOへアップロードする操作は外部への書き込みであるため、Codexへ依頼する場合は送信直前に別途GOする。

## 3. DEVプロファイルへの先行導入

1. `npm run experiment`で起動したFirefoxが残っている場合は終了する。
2. DEVプロファイルを通常起動する。
3. 「アドオンとテーマ」を開き、歯車メニューから「ファイルからアドオンをインストール」を選ぶ。
4. AMOから取得した署名済みXPIを選び、表示されたアドオンIDとバージョンを確認して追加する。
5. Bookumarkを開き、production版として実rootから起動することを確認する。

## 4. 実務プロファイルへの導入

DEVプロファイルで署名済み版の基本動作を確認してから、同じ署名済みXPIを実務プロファイルへ導入する。
導入方法はDEVと同じ「ファイルからアドオンをインストール」を使用する。未署名ZIPやソースZIPは選ばない。

## 5. DEVの二つの入口

- 署名済み版: DEVプロファイルを通常起動する。production版として実rootを使用する。
- 一時開発版: リポジトリから`npm run experiment`を実行する。development専用機能を有効にする。

両者は同じアドオンIDを使うため同時に使用しない。experimentを終了した後はDEVプロファイルを通常起動し、
「アドオンとテーマ」で署名済み版のバージョンと有効状態を確認してから検証を再開する。

## 6. 更新時

1. package、lockfile、manifestのバージョンを同じ新しい値へ上げる。
2. テスト、lint、`npm run build:amo`を再実行する。
3. AMOの同じアドオンIDへ新しいunlisted版を手動提出する。
4. 新しい署名済みXPIをDEVで先行確認し、その後に実務プロファイルへ手動導入する。

unlisted版には自前の`update_url`を設けていないため、自動更新を前提にしない。
